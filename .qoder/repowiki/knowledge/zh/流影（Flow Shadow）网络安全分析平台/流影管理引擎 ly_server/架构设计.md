模块采用三层静态/动态库分层构建：
- `src/common`：基础工具与协议层，编译为静态库 `libcommon.a` 和共享库 `libcommon.so`，内含 rapidjson/cJSON、日志、HTTP、INI、时间、IP、MD5/SHA256、mmap、线程池等通用组件，并通过 protobuf（cache/config/mo/event/policy/feature/ctl/topn/domaininfo/evidence）定义跨进程消息格式；`baseline/` 子目录提供缓存与槽位管理器。
- `src/lib`：可插拔的配置加载器，每个 `config_*.so`（event/mo/internalip/internalsrv/agent/bwlist/user）实现统一的 `config_class.cpp` 抽象，由上层按需动态加载，依赖 `../common` 的 libcommon。
- `src/server`：业务入口，每个 `.cpp` 对应一个独立的 CGI 可执行文件（mo/internalip/event/bwlist/feature/event_feature/config/auth/sctl/evidence/threatinfo 等），通过 `Makefile` 中的 `WWW_EXES` 列表统一产出并安装到 `/Server/www/d`；另有独立二进制 `config_pusher`、`gen_event` 安装至 `/Server/bin`，由 cron 每 5 分钟调度。
- 数据访问统一经 `dbc.h/.cpp` 封装 cppdb + MySQL/MariaDB，所有 SQL 查询集中在该层；控制面通过 `sctl.cpp` 调用 `systemctl` 启停子系统服务。
- 依赖方向严格自上而下：server → lib(common) → 外部库（protobuf/cppdb/cgicc/curl/boost/mysql），lib 仅依赖 common，common 不反向依赖 server。
